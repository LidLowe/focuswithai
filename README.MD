# FocusWithAI

FocusWithAI ведёт рабочие спринты. Gemini Live оценивает активность относительно цели
спринта, а HUD показывает уровень отвлечения. Приложение запускается на Windows и
открывает локальную панель на [127.0.0.1:8765](http://127.0.0.1:8765/#/current).

## Запуск

1. Установи Python 3.10 или новее и запусти `start.bat`. При первом запуске скрипт
   создаст `.venv` и установит зависимости. С готовым окружением приложение
   можно открыть через `FocusWithAI.cmd`.
2. В разделе **Gemini Live** выбери модель и голос, введи ключ Gemini API и разреши
   отправку текстового контекста. В блоке проверки **Подключение** проверяет
   открытие WebSocket и setupComplete. **Классификация** дополнительно запрашивает
   оценку синтетической задачи. **Нативное аудио** также проверяет получение PCM16
   24 кГц для синтетической реплики. Звук в диагностике не воспроизводится.
3. Сохрани настройки, перезапусти трекер и создай спринт. Для быстрого старта
   достаточно цели. В истории доступны отчёты, подтверждение результата и повтор
   спринта. Черновики и шаблоны находятся в разделе текущего спринта.

| Модель | API model ID | Вызов функции |
| --- | --- | --- |
| Gemini 3.8 Live | `gemini-3.8-live` | Синхронный |
| Gemini 3.8 Live Extended Thinking | `gemini-3.8-live-extended-thinking` | Асинхронный |

По умолчанию выбран голос Charon. Манеру речи можно настроить пользовательским
системным промптом. **Инициативные комментарии** включаются отдельно. Для ручной
проверки голоса попроси предложить следующий шаг и вернись в окно рабочей задачи.
[Модели и форматы Live API](https://aistudio.google.com/docs/live-api/capabilities) ·
[Вызов функций](https://aistudio.google.com/docs/live-api/tools)

## Контекст и вмешательства

WebSocket открывается при запуске спринта из панели и закрывается при его завершении
или отмене. Пауза, перерыв, исключённые приложения и вкладки без разрешённого
контекста приостанавливают анализ и очищают текущую оценку. При возвращении к
разрешённому окну анализ продолжается через то же соединение. После серверного
GoAway или сетевого сбоя приложение переподключается. FocusWithAI передаёт
цель, разрешённые наблюдения и короткую историю рабочей активности и предупреждений.
Для контекста вкладки добавь рабочий домен в **Контекст активности**, загрузи папку
`browser_extension` как распакованное расширение Chrome или Edge и включи передачу
на нужной вкладке. Метаданные медиа и список работающих приложений включаются
отдельно. Их наличие само по себе не доказывает отвлечение.

В активном спринте открой **Контекст активности** и нажми **Включить автозахват**.
FocusWithAI следует за активным окном. Windows PrintWindow захватывает само окно,
включая отрисованное содержимое Chrome. По умолчанию проверка идёт каждые 2 с.
FocusWithAI уменьшает кадр до 1280×720 и сжимает в JPEG с качеством 80. Для неподвижного окна
проверки становятся реже. Следующий ход получает только последний актуальный JPEG.

Отдельно включи **Передавать изображения в Gemini**, чтобы модель получала кадры.
Локальный предпросмотр доступен и при выключенной отправке. Кадры хранятся в памяти.
Автозахват приостанавливается вместе со спринтом и выключается при завершении.
Кнопка остановки и горячая клавиша Ctrl+Shift+F9 сразу очищают текущий кадр.

Обычным приложениям достаточно локальных проверок окна. Для Chrome проверяются
профиль, активная вкладка, документ и защищённые поля. Без URL можно захватить
проверенную страницу, если список рабочих доменов пуст. Заполненный список
ограничивает захват: для проверки домена требуется адрес. Расширение добавляет
разрешённые метаданные вкладки. Если браузер, вкладка или документ недоступны для
проверки (например, браузер не отдаёт дерево доступности), пропускается только изображение. Gemini продолжает получать остальные
разрешённые источники. При недостатке сведений результат — UNCERTAIN.
Dashboard отдельно показывает состояние соединения, захвата, анализа и звука,
число кадров и оценок, время, размеры и причины пропуска.

Шкала растёт только на основе подтверждённого отвлечения. Пауза и перерыв
останавливают анализ. При потере соединения текущая оценка сбрасывается.
Временные ограничения включаются пользователем для конкретного спринта.
`Ctrl+Shift+F9` прекращает захват и вмешательства. **Остановить звук** прерывает
текущий сигнал или реплику.

## Профайлер производительности

Открой **Производительность** в Dashboard и нажми **Начать запись**. Продолжай
работать со спринтом как обычно. Профайлер по умолчанию выключен и работает
независимо от согласия на отправку кадров. **Остановить запись** оставляет
результаты для просмотра и выгрузки. Новый запуск создаёт новую запись. Сброс при
работающем профайлере начинает её заново. CSV и JSON скачиваются на компьютер.
Экспорт содержит конфигурацию измеряемого конвейера, метки времени и обезличенные
идентификаторы спринтов, наблюдений, ходов и кадров. В нём нет содержимого кадров,
аудио, промптов, заголовков окон и API-ключей.

| Измерение | Границы |
|---|---|
| Активное окно | Вызов получения HWND, заголовка и пути процесса. |
| Захват Windows | Чтение пикселей окна через PrintWindow, включая копирование из GDI. |
| Проверка браузера | Локальные проверки до и после захвата. Время самого захвата и обработки картинки исключено. |
| Масштабирование, JPEG, дедупликация | Изменение размера, преобразование и кодирование JPEG, сравнение отпечатков кадров соответственно. |
| От JPEG до очереди | От завершения кодирования до постановки отправленного кадра в очередь, включая дедупликацию и ожидание актуального наблюдения. |
| Очередь хода | От постановки события хода до передачи транспорту, за вычетом ожидания предыдущего хода. |
| Очередь JPEG | От постановки JPEG в очередь до подготовки хода. Включает ожидание предыдущего хода и поэтому пересекается с ним. |
| Предыдущий ход | Доля ожидания готовности Gemini, которая пришлась на фактическое ожидание подготовленного хода. |
| Base64 и сериализация | Преобразование JPEG в Base64 и построение JSON, включая сериализацию вложенного текстового контекста. |
| Локальная отправка | От завершения сериализации до возврата из отправки WebSocket. Получение сервером и время его вычислений отдельно недоступны. |
| Первый ответ и валидный toolCall | От локальной отправки до первого сообщения, относящегося к ходу, и до проверки структурированного результата. Включает сеть, очередь сервера и обработку ответа. |
| Принятая классификация | От локальной отправки до принятия структурированной оценки текущего наблюдения. Может включать отправку ответа на toolCall. |
| Первый PCM | От локальной отправки до получения первого валидного аудиофрагмента. Отдельно измеряется задержка после отправки ответа на toolCall. |
| Передача микшеру | От локальной отправки до принятия первого фрагмента микшером. Задержка PCM → микшер включает локальный буфер, ожидание аудиоканала и сигнал перед речью. Момент звука на устройстве не измеряется. |
| От кадра до классификации | От начала захвата JPEG, фактически приложенного к этому ходу, до принятия его оценки. Для хода без нового JPEG и для устаревшей оценки замер отсутствует. |

Размеры WebSocket считаются по полезной нагрузке сообщений приложения, без
служебных заголовков, транспортного сжатия, TLS и TCP. Исходящий объём учитывает
завершившиеся локальные записи. CPU измеряется по времени процесса backend
(100% соответствует одному логическому ядру). RAM на Windows — текущий рабочий
набор backend. Расход профайлера показывает среднее и максимальное время
помещения события в очередь и CPU фонового агрегатора. Эти замеры не включают
весь косвенный расход включённой инструментации.

Токены — поля [UsageMetadata](https://aistudio.google.com/api-reference/live#UsageMetadata).
Последнее значение каждого поля в завершённом ходе учитывается один раз.
Частичные данные незавершённого хода отмечены отдельно. Сумма по ходам может
повторно учитывать историю и кэш и не показывает стоимость.

У агрегации ограничены очередь и история. Окна 1, 5 и 15 минут используют слоты
по 5 секунд, поэтому граница может включать соседние несколько секунд. Среднее,
минимум, максимум и популяционное стандартное отклонение рассчитываются по
принятым измерениям. P50/P90/P95/P99 приближены логарифмической гистограммой.
Отсутствующие измерения не участвуют в расчёте. Итоги за текущий спринт и всю
запись сохраняются при вытеснении отдельных строк. В CSV и JSON остаются
последние 12 000 принятых событий. При перегрузке счётчик отбрасывания показывает
замеры, которые не попали в очередь.

## Сигналы и голос

В панели **Сигналы и голосовые пакеты** доступны пять режимов: только сигналы,
только голосовой пакет, только Gemini Live, сигнал и голосовой пакет, сигнал и
Gemini Live. Режим Live воспроизводит нативный PCM модели. В комбинированных
режимах сигнал звучит первым. Пауза по умолчанию составляет 300 мс. Громкость
эффектов, пакетов и Live Audio регулируется отдельно.

Пакеты находятся в `assets/alarms/`, `assets/voicepacks/` и `voicepacks/`.
У каждого пакета есть `manifest.json` и папки событий с именами в нижнем регистре.
Панель импортирует клипы, проигрывает предпросмотр и позволяет назначить клип
для другого события. Допустимы WAV, MP3 и OGG до 16 МиБ и 30 секунд.

### Импорт StarCraft и Brood War

Импортируй звуки из своей локальной установки или предоставленных ZIP-архивов.

```powershell
.\.venv\Scripts\python.exe audio_import.py 'D:\Games\StarCraft'
.\.venv\Scripts\python.exe audio_import.py 'D:\Audio\Interface.zip' 'D:\Audio\Terran.zip'
.\.venv\Scripts\python.exe audio_import.py --demo
```

Для прямого импорта классических MPQ нужен локальный Unicode `StormLib.dll`
в `.runtime/stormlib/` или путь через `--stormlib`. Команда `--demo` создаёт
оригинальные тестовые сигналы. После импорта обнови список пакетов в панели
и выбери нужные эффекты и голоса. В репозитории находятся манифесты. Импортированные
записи остаются локальными. [StormLib](https://github.com/ladislav-zezula/StormLib/releases)

## Автозапуск и конфигурация

В разделе **Автозапуск** можно зарегистрировать задачу Windows для текущего
пользователя. Лаунчер защищён от второго экземпляра. Он запускает Dashboard и
HUD, показывает состояние в трее и перезапускает принадлежащий ему процесс
после сбоя. Gemini подключается при активном спринте или явной проверке в панели.

Настройки хранятся в `config.json`, история и шаблоны — в `sprints.json`.
На Windows ключ Gemini хранится в диспетчере учётных данных. При переходе
со старой схемы приложение сохраняет `config.pre-gemini-live.json` с прежними
настройками без ключей. Разрешение на передачу контекста сохраняется только
если Gemini Live уже был выбран. При переходе с ручного захвата настройки
сохраняются в `config.pre-auto-capture.json`. Автозахват включается отдельно в каждом
спринте. Локальные модели и пользовательские звуки остаются на диске.

## Архитектура и тесты

`FocusController` собирает контекст. `ContextStream` ограничивает очередь и
отмечает поколение наблюдений. `LiveSession` ведёт сессию и использует
`GeminiLiveTransport`. `DecisionEngine` и `CommentaryGate` проверяют результаты
локально. `LiveAudio` и движки звуковых пакетов делят один канал воспроизведения.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check panel_web/app.js
```

Автоматизированные тесты используют тестовый транспорт и локальный WebSocket,
включая проверки структурированной оценки, кадров, нативного PCM, инициативной
реплики, спринтов и восстановления после разрыва.

Для ручной проверки с действительным ключом сначала выполни три проверки в
**Gemini Live**. Начни спринт в Dashboard. В разрешённой IDE дождись состояния
`CONNECTED / READY` и классификации. Переключись в браузер без разрешённой вкладки,
затем обратно в IDE. Повтори с приложением из исключений. В исключённых окнах
ожидай `CONNECTED / WAITING_FOR_CONTEXT / SILENT` и `UNCERTAIN`. После возврата
проверь новую оценку и непрерывный счётчик времени соединения. После завершения
спринта соединение переходит в `DISCONNECTED`. Уровень журнала 3 в **Диагностике**
показывает этапы WebSocket и причины блокировки. Журнал содержит типы событий,
статусы и размеры данных.

Проверки с настоящим Gemini API используют сохранённый ключ и синтетические данные.
Первая прогоняет временный спринт с тестовыми наблюдениями Chrome и IDE, JPEG и
нативным аудио. Вторая проверяет, что модель прочитала случайное число из JPEG:
тест сравнивает ответ с оригиналом, а число присутствует только на изображении.
Запускай проверки из обычного пользовательского PowerShell с разрешением на
текстовый контекст.

```powershell
$env:FOCUSWITHAI_TEST_GOOGLE = '1'
$env:PYTHONPATH = 'tests'
.\.venv\Scripts\python.exe -m unittest test_gemini_live.SprintWebSocketTests.test_real_gemini_sprint_and_native_audio -v
.\.venv\Scripts\python.exe -m unittest test_gemini_live.SprintWebSocketTests.test_real_gemini_reads_random_number_from_jpeg -v
```

JPEG передаётся в [ходе Gemini Live](https://aistudio.google.com/api-reference/live#BidiGenerateContentClientContent)
как [inlineData](https://aistudio.google.com/api-reference/generate-content#Resource:Content)
с MIME-типом image/jpeg и base64. Счётчик отправки обновляется после записи сообщения
в WebSocket. Обработку изображения моделью проверяет тест распознавания.
