# FocusWithAI

FocusWithAI ведёт рабочие спринты. Gemini Live оценивает активность относительно цели
спринта, а HUD показывает уровень отвлечения. Приложение запускается на Windows и
открывает локальную панель на [127.0.0.1:8765](http://127.0.0.1:8765/#/current).

## Запуск

1. Установи Python 3.10 или новее и запусти `start.bat`. При первом запуске скрипт
   создаст `.venv` и установит зависимости. С готовым окружением приложение
   можно открыть через `FocusWithAI.cmd`.
2. В разделе **Gemini Live** выбери модель и голос, введи ключ Gemini API и разреши
   отправку текстового контекста. В блоке проверки **Подключение** проверяет
   открытие WebSocket и setupComplete. **Классификация** дополнительно запрашивает
   оценку синтетической задачи. **Нативное аудио** также проверяет получение PCM16
   24 кГц для синтетической реплики. Звук в диагностике не воспроизводится.
3. Сохрани настройки, перезапусти трекер и создай спринт. Для быстрого старта
   достаточно цели. В истории доступны отчёты, подтверждение результата и повтор
   спринта. Черновики и шаблоны находятся в разделе текущего спринта.

| Модель | API model ID | Вызов функции |
| --- | --- | --- |
| Gemini 3.8 Live | `gemini-3.8-live` | Синхронный |
| Gemini 3.8 Live Extended Thinking | `gemini-3.8-live-extended-thinking` | Асинхронный |

По умолчанию выбран голос Charon. Манеру речи можно настроить пользовательским
системным промптом. **Инициативные комментарии** включаются отдельно. Для ручной
проверки голоса попроси предложить следующий шаг и вернись в окно рабочей задачи.
[Модели и форматы Live API](https://aistudio.google.com/docs/live-api/capabilities) ·
[Вызов функций](https://aistudio.google.com/docs/live-api/tools)

## Контекст и вмешательства

WebSocket открывается при запуске спринта из панели и закрывается при его завершении
или отмене. Пауза, перерыв, исключённые приложения и вкладки без разрешённого
контекста приостанавливают анализ и очищают текущую оценку. При возвращении к
разрешённому окну анализ продолжается через то же соединение. После серверного
GoAway или сетевого сбоя приложение переподключается. FocusWithAI передаёт
цель, разрешённые наблюдения и короткую историю рабочей активности и предупреждений.
Для контекста вкладки добавь рабочий домен в **Контекст активности**, загрузи папку
`browser_extension` как распакованное расширение Chrome или Edge и включи передачу
на нужной вкладке. Метаданные медиа и список работающих приложений включаются
отдельно. Их наличие само по себе не доказывает отвлечение.

Чтобы передавать кадры, отдельно разреши это в **Gemini Live**, включи ручной захват
в **Контекст активности**, добавь полный путь к EXE и выбери окно в активном спринте.
Фильтры исключают чувствительные окна. Кадры находятся в памяти. **Диагностика**
показывает контекст, классификацию, состояние Live-сессии и журнал.

Шкала растёт только на основе подтверждённого отвлечения. Пауза и перерыв
останавливают анализ. При потере соединения текущая оценка сбрасывается.
Временные ограничения включаются пользователем для конкретного спринта.
`Ctrl+Shift+F9` прекращает захват и вмешательства. **Остановить звук** прерывает
текущий сигнал или реплику.

## Сигналы и голос

В панели **Сигналы и голосовые пакеты** доступны пять режимов: только сигналы,
только голосовой пакет, только Gemini Live, сигнал и голосовой пакет, сигнал и
Gemini Live. Режим Live воспроизводит нативный PCM модели. В комбинированных
режимах сигнал звучит первым. Пауза по умолчанию составляет 300 мс. Громкость
эффектов, пакетов и Live Audio регулируется отдельно.

Пакеты находятся в `assets/alarms/`, `assets/voicepacks/` и `voicepacks/`.
У каждого пакета есть `manifest.json` и папки событий с именами в нижнем регистре.
Панель импортирует клипы, проигрывает предпросмотр и позволяет назначить клип
для другого события. Допустимы WAV, MP3 и OGG до 16 МиБ и 30 секунд.

### Импорт StarCraft и Brood War

Импортируй звуки из своей локальной установки или предоставленных ZIP-архивов.

```powershell
.\.venv\Scripts\python.exe audio_import.py 'D:\Games\StarCraft'
.\.venv\Scripts\python.exe audio_import.py 'D:\Audio\Interface.zip' 'D:\Audio\Terran.zip'
.\.venv\Scripts\python.exe audio_import.py --demo
```

Для прямого импорта классических MPQ нужен локальный Unicode `StormLib.dll`
в `.runtime/stormlib/` или путь через `--stormlib`. Команда `--demo` создаёт
оригинальные тестовые сигналы. После импорта обнови список пакетов в панели
и выбери нужные эффекты и голоса. В репозитории находятся манифесты. Импортированные
записи остаются локальными. [StormLib](https://github.com/ladislav-zezula/StormLib/releases)

## Автозапуск и конфигурация

В разделе **Автозапуск** можно зарегистрировать задачу Windows для текущего
пользователя. Лаунчер защищён от второго экземпляра. Он запускает Dashboard и
HUD, показывает состояние в трее и перезапускает принадлежащий ему процесс
после сбоя. Gemini подключается при активном спринте или явной проверке в панели.

Настройки хранятся в `config.json`, история и шаблоны — в `sprints.json`.
На Windows ключ Gemini хранится в диспетчере учётных данных. Перед переходом
на схему 2 приложение сохраняет `config.pre-gemini-live.json` с прежними
настройками без ключей. Разрешение на передачу контекста сохраняется только
если Gemini Live уже был выбран. Локальные модели и пользовательские звуки
остаются на диске.

## Архитектура и тесты

`FocusController` собирает контекст. `ContextStream` ограничивает очередь и
отмечает поколение наблюдений. `LiveSession` ведёт сессию и использует
`GeminiLiveTransport`. `DecisionEngine` и `CommentaryGate` проверяют результаты
локально. `LiveAudio` и движки звуковых пакетов делят один канал воспроизведения.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check panel_web/app.js
```

Автоматизированные тесты используют тестовый транспорт и локальный WebSocket,
включая проверки структурированной оценки, кадров, нативного PCM, инициативной
реплики, спринтов и восстановления после разрыва.

Для ручной проверки с действительным ключом сначала выполни три проверки в
**Gemini Live**. Начни спринт в Dashboard. В разрешённой IDE дождись состояния
`CONNECTED / READY` и классификации. Переключись в браузер без разрешённой вкладки,
затем обратно в IDE. Повтори с приложением из исключений. В исключённых окнах
ожидай `CONNECTED / WAITING_FOR_CONTEXT / SILENT` и `UNCERTAIN`. После возврата
проверь новую оценку и непрерывный счётчик времени соединения. После завершения
спринта соединение переходит в `DISCONNECTED`. Уровень журнала 3 в **Диагностике**
показывает этапы WebSocket и причины блокировки. Журнал содержит типы событий,
статусы и размеры данных.

Автоматическая проверка с настоящим Gemini API использует сохранённый ключ,
отдельный временный спринт и синтетические окна. Запусти её из обычного
пользовательского PowerShell с включённым разрешением на текстовый контекст.

```powershell
$env:FOCUSWITHAI_TEST_GOOGLE = '1'
$env:PYTHONPATH = 'tests'
.\.venv\Scripts\python.exe -m unittest test_gemini_live.SprintWebSocketTests.test_real_gemini_sprint_and_native_audio -v
```
